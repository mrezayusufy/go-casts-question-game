# GameApp – A Simple Multiplayer Quiz Platform  

**GameApp** is a lightweight Go‑based backend that powers a multiplayer quiz game.  
It focuses on clear domain modeling, easy extensibility, and a straightforward API.  

---

## 1. Project Overview  

- **Language**: Go (v1.20+ recommended)  
- **Architecture**: Clean‑architecture style – domain entities are defined in the `entity` package, business logic lives in services, and the HTTP layer exposes REST endpoints.  
- **Persistence**: Any SQL database that works with an ORM (e.g., GORM) or raw `database/sql`.  

The core domain consists of four entities: `Category`, `Game`, `Question`, and `User`.  These are defined in the `entity` package – see below for the struct definitions.  

---

## 2. Domain Entities  

| Entity | Key Fields | Purpose |
|--------|------------|---------|
| **Category** | `ID`, `Name`, `Description` | Groups questions into thematic areas. | <sup>[1]</sup> |
| **Game** | `ID`, `CategoryID`, `QuestionIDs`, `Player` | Represents an active game session. | <sup>[2]</sup> |
| **Player** | `ID`, `UserID`, `GameID`, `Score`, `Answers` | Tracks a user's participation in a game. | <sup>[2]</sup> |
| **PlayerAnswer** | `ID`, `PlayerID`, `QuestionID`, `Choice` | Stores a single answer given by a player. | <sup>[2]</sup> |
| **Question** | `ID`, `Text`, `PossibleAnswers`, `CorrectAnswerID`, `Difficulty`, `CategoryID` | Defines a quiz question. | <sup>[3]</sup> |
| **PossibleAnswer** | `ID`, `Text`, `Choice` | Each potential answer to a question. | <sup>[3]</sup> |
| **Answer** | `ID`, `PlayerID`, `QuestionID` | Historical record of a player’s answer (used for analytics). | <sup>[3]</sup> |
| **User** | `ID`, `PhoneNumber`, `Name` | Represents a registered player. | <sup>[4]</sup> |

### Enums and Validation  

- `PossibleAnswerChoice` (`A`, `B`, `C`, `D`) – validated via `IsValid()` [<sup>[3]</sup>].  
- `QuestionDifficulty` (`Easy`, `Medium`, `Hard`) – also validated with `IsValid()` [<sup>[3]</sup>].  

---

## 3. Typical Workflow  

1. **Create a Category** – define a new theme for questions.  
2. **Add Questions** – attach questions to the category, specifying correct answer and difficulty.  
3. **Launch a Game** – select a category and generate a list of `QuestionIDs`.  
4. **Players Join** – each `Player` record is created, linked to a `User`.  
5. **Answering** – players submit `PlayerAnswer` entries.  
6. **Scoring** – after all questions or a timed interval, calculate scores and update `Player.Score`.  
7. **Leaderboard** – expose a sorted list of players for the game.

## 4. Sample Code (Go)  

```go
// Create a new question
q := entity.Question{
    Text: "What is the capital of France?",
    PossibleAnswers: []entity.PossibleAnswer{
        {Text: "Paris", Choice: entity.PossibleAnswerA},
        {Text: "Rome",   Choice: entity.PossibleAnswerB},
        {Text: "Berlin", Choice: entity.PossibleAnswerC},
        {Text: "Madrid", Choice: entity.PossibleAnswerD},
    },
    CorrectAnswerID: 1,
    Difficulty:     entity.QuestionDifficultyEasy,
    CategoryID:     1,
}
```

## 5. Getting Started  

1. **Clone the repo**  
   ```bash
   git clone https://github.com/bertina/gameapp.git
   cd gameapp
   ```  
2. **Configure the database** – set environment variables (`DB_DSN`, etc.).  
3. **Run migrations** (example with GORM)  
   ```bash
   go run cmd/migrate/main.go
   ```  
4. **Start the server**  
   ```bash
   go run cmd/server/main.go
   ```  
5. **API** – accessible at `http://localhost:8080`. Refer to the autogenerated Swagger docs for endpoints.

---

## 6. Extending the Project  

- **Add new question types** (e.g., multiple‑select) by extending the `Question` struct and validation logic.  
- **Implement real‑time updates** using WebSockets or Server‑Sent Events for instant scoreboards.  
- **Introduce authentication** (JWT/OAuth) to secure endpoints.
